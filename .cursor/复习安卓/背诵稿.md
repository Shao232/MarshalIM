## 一、Handler

**是什么**  
Handler 是线程间通信。四个角色：Handler、Message、MessageQueue、Looper。  
一个线程一个 Looper，放在 ThreadLocal 里。主线程 Looper 启动时就已经 prepare + loop，不用自己建。

**切到主线程**  
Handler 在主线程创建（或 `Handler(Looper.getMainLooper())`）。  
子线程用这个 Handler 调 `sendMessage` / `post`（发）。  
主线程 `Looper.loop()` 里 `queue.next()`（取）。  
`msg.target.dispatchMessage` → `handleMessage`（执行，这时才能碰 UI）。  
记：子线程发，主线程取，主线程执行。

**ThreadLocal**  
每个线程自己的一份变量，不是线程池。Looper 用它做到一线程一份。  
`new Handler()` 从 ThreadLocal 取当前 Looper，子线程没 prepare 就是 null，崩。

**死循环为什么不 ANR**  
没消息时卡在 `nativePollOnce`，底层 epoll_wait，内核堵住，不占 CPU。有人发消息才 nativeWake。  
loop 不是卡顿原因，往主线程塞耗时才是。  
5 秒只是触摸/点击；广播 10s、前台 Service 20s，不是所有 ANR 都是 5 秒。

**泄漏**  
链：MessageQueue → Message.target → Handler（非静态内部类）→ Activity。  
根因：Message 比 Activity 活得长（postDelayed 还在队列里）。  
修：静态内部类 + WeakReference；onDestroy 里 `removeCallbacksAndMessages(null)`。

**子线程 new Handler**  
默认不行，没有 Looper。三步：`prepare` → `new Handler` → `loop`。或用 HandlerThread。  
这套 handleMessage 跑在后台线程，不是主线程。

## 二、Activity 生命周期

**A 跳 B**  
`A.onPause → B.onCreate → B.onStart → B.onResume → A.onStop`  
A.onStop 在 B.onResume 后面，让新页尽快可见。  
onPause 不能耗时，下一个 onCreate 要等它跑完。

**B 返回 A**  
`B.onPause → A.onRestart → A.onStart → A.onResume → B.onStop → B.onDestroy`

**场景**  
HOME / 锁屏：Pause → Stop。回前台：Restart → Start → Resume。  
普通 Dialog：是 View，不走生命周期。  
Dialog 主题的 Activity：下面那个只 Pause，不 Stop。  
旋转没配 configChanges：Pause → Stop → Destroy → Create → Start → Resume。

## 三、Service

跑在主线程，耗时自己开线程。必须 Manifest 登记。

**方法**  
onCreate：第一次拉起，只一次。  
onStartCommand：每次 start 都走。  
onBind：第一次 bind，返回 Binder；默认只一次。  
onUnbind：最后一个客户端解绑。  
onRebind：上次 onUnbind 返回 true 再 bind。  
onDestroy：没人 start 且没人 bind。

**两条线**  
start：onCreate → onStartCommand（可多次）→ stop → onDestroy。  
bind：onCreate → onBind → 全 unbind → onUnbind → onDestroy。  
混合：stop + 全 unbind 才销毁。

**BIND_AUTO_CREATE**  
服务不在就先 onCreate 再 bind。不等于 startService。  
只靠它拉起来的，人全 unbind 就会销毁。

**Binder**  
绑定后给页面的手柄。继承 Binder，onBind 交出去。  
Activity 在 onServiceConnected 里转成自己的 Binder，再 getService() 调方法。  
start 只能拉起来，bind + Binder 才能互相调。

## 四、MVC / MVP / MVVM

都是 M 数据、V 界面、中间层调度。差在中间层认不认具体页面。

MVC：Activity 常既是 V 又是 C，中间层还能 setText。容易膨胀。  
MVP：Presenter 只认 View 接口，喊 showXxx，不碰控件。要 detach。  
MVVM：ViewModel 不持有 View，只改 LiveData，页面自己观察。旋转数据还在。

没接口、还能找控件 = 还是 MVC。  
只喊 showXxx = MVP。  
只改数据、页面观察 = MVVM。

项目：多数页偏 MVC，别吹全项目 MVVM。

**LiveData 倒灌**  
LiveData 粘性：后订阅立刻拿到最后一条。旋转后新 observe，Toast/跳转会再来一次。  
因为新观察者 lastVersion=-1，小于内部 mVersion，一可见就派发当前值。  
状态（列表）该粘；事件不该粘。事件用 SingleLiveEvent 或 SharedFlow(replay=0)。

## 五、网络 OkHttp + Retrofit

**分工**  
OkHttp 真发网。Retrofit 动态代理翻译方法，不发网。  
`create(Api)` 的实现类是框架生成的，不是手写 Impl。

**创建**  
先 `OkHttpClient.Builder`（超时、拦截器），应单例复用。  
再 `Retrofit.Builder().client(okHttp).baseUrl().addConverter().addCallAdapter().build()`。  
`service.getBanner()` → 读 @GET 拼 Request → OkHttp 责任链 → Gson 转对象。

**两种拦截器**  
addInterceptor：最外层，一次请求只走一遍，缓存命中也走。加 Token、日志。  
addNetworkInterceptor：每次真上网都走，缓存命中不走。看真实报文。  
外面看最终账，里面看线路上每一次。

**CallAdapter vs Converter**  
Converter：JSON ↔ 对象，GsonConverterFactory。  
CallAdapter：怎么执行、返回啥，RxJava2CallAdapterFactory / suspend。

**Dispatcher**  
限流不在线程池，在 Dispatcher。  
maxRequests=64，maxRequestsPerHost=5。超了进 readyAsyncCalls。

**缓存**  
默认没有。自己 `.cache(Cache(目录, 大小))`，还要 Cache-Control。

**设计模式**  
OkHttp 最核心：责任链（拦截器 proceed）。还有 Builder、newCall 工厂、连接池享元、Callback 观察者。  
Retrofit 最核心：动态代理。还有 Builder、外观、CallAdapter 适配器、Converter 工厂、ServiceMethod 缓存。  
真正上网的只有 OkHttp。
