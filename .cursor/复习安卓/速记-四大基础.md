# 四大基础速记

## Handler ⭐

一句话：把任务投到目标线程的消息队列，由那个线程的 Looper 取出来串行执行。

四件套：Handler / Message / MessageQueue / Looper  
一个线程一个 Looper，存在 ThreadLocal（每个线程一份独立值，互不影响）。主线程 Looper 在 `ActivityThread.main()` 里 `prepareMainLooper + loop`。

流程：`sendMessage` 把 `msg.target=Handler`，按 `when` 插入单链表，`nativeWake` 唤醒 → `loop` 调 `queue.next()` → `msg.target.dispatchMessage`。

### 三个必追

1. **死循环为什么不卡死 / 不 ANR？**  
   没消息时阻塞在 `nativePollOnce`（epoll），不占 CPU。ANR 是主线程有消息却处理不完（耗时），不是 loop 本身。

2. **为什么泄漏？怎么修？**  
   链：`MessageQueue → Message.target → Handler(非静态内部类) → Activity`。根因是消息比 Activity 活得长。  
   修：静态内部类 + WeakReference；`onDestroy` 里 `removeCallbacksAndMessages(null)`。

3. **子线程能直接 new Handler 吗？**  
   不能，没 Looper。要 `prepare → new Handler → loop`，或用 HandlerThread。

加分：IdleHandler（空闲延迟初始化）、同步屏障（target=null，异步消息插队）、`Message.obtain()` 复用。

## View 绘制

入口：`ViewRootImpl.performTraversals()`（onResume 之后窗口交给 WMS 才创建）。  
顺序：measure → layout → draw。

- measure：DecorView 往下传 MeasureSpec，`setMeasuredDimension` 存宽高。ViewGroup 先量子再算自己。
- layout：定 left/top/right/bottom。
- draw：背景 → onDraw → dispatchDraw → 装饰。自定义主要重写 onDraw。

### MeasureSpec

32 位：高 2 位 mode，低 30 位 size。  
EXACTLY（match_parent / 具体 dp）· AT_MOST（wrap_content）· UNSPECIFIED（ScrollView 等）。  
口诀：除了 match_parent 和具体值能拿 EXACTLY，wrap_content 一律 AT_MOST。

### 四个必追

1. **onCreate 里 getWidth=0？** 还没 measure/layout。解：`view.post {}` / OnGlobalLayoutListener / onWindowFocusChanged。
2. **requestLayout vs invalidate**：前者整套遍历（改尺寸位置）；后者只 draw（改显示）。子线程用 `postInvalidate`。
3. **自定义 View**：构造要有 AttributeSet；onMeasure 必须处理 wrap_content（默认和 match_parent 一样）；onDraw 里别 new 对象；ViewGroup 还要 onLayout。
4. **getMeasuredWidth vs getWidth**：前者 measure 结果，后者 `right-left`。layout 传了不同值才会不等。

## Activity 生命周期

三层：完整 Create→Destroy · 可见 Start→Stop · 前台 Resume→Pause。

**A 跳 B（必背）**：`A.onPause → B.onCreate → B.onStart → B.onResume → A.onStop`  
B 返回 A：`B.onPause → A.onRestart → A.onStart → A.onResume → B.onStop → B.onDestroy`  
onPause 不能耗时：下一个 Activity 的 onCreate 要等它跑完。

| 场景 | 流程 |
|---|---|
| HOME / 锁屏 | Pause → Stop |
| 回前台 | Restart → Start → Resume |
| 普通 Dialog | 不走生命周期 |
| Dialog 主题 Activity | 只 Pause，不 Stop |
| 旋转（未配 configChanges） | 销毁重建 |
| 旋转（配了 orientation\|screenSize） | onConfigurationChanged |

onSaveInstanceState：可能被系统销毁时才调，用户按返回不调。恢复在 onCreate 或 onRestoreInstanceState（onStart 之后，Bundle 非空）。

启动模式：standard 每次新建 · singleTop 栈顶复用走 onNewIntent · singleTask 栈内唯一清上面 · singleInstance 独占任务栈。  
Flag 会覆盖清单模式。

启动流程加分：startActivity → Instrumentation → AMS(Binder) → ApplicationThread → H 切主线程 → handleLaunchActivity → 反射创建 → attach → onCreate。

## 四大组件

一句话：Activity 管界面，Service 管后台，Receiver 管监听，Provider 管数据共享；四个都经 AMS + Binder 调度，所以必须 Manifest 注册。

### Service

必会的生命周期方法：

| 方法 | 何时 | 几次 |
|---|---|---|
| **onCreate** | 第一次被拉起 | 整段生命只一次 |
| **onStartCommand** | 每次 startService | 每次 start 都走 |
| **onBind** | 第一次 bind | 默认只一次，后续复用同一个 Binder |
| **onUnbind** | 最后一个客户端解绑 | 全解绑时 |
| **onRebind** | 上次 onUnbind 返回 true，再次 bind | 可选 |
| **onDestroy** | 没人 start 且没人 bind | 一次，在这释放资源 |

两条线：

```
start：onCreate → onStartCommand（可多次）→ stop → onDestroy
bind ：onCreate → onBind → 全 unbind → onUnbind → onDestroy
混合：既 start 又 bind，要 stop + 全 unbind 才 onDestroy
```

- **跑在主线程**，耗时自己开线程。
- 8.0+ 长期后台用前台服务 + 通知。`startForegroundService` 后 5 秒内必须 `startForeground`。
- 返回值：STICKY 重启 Intent=null · NOT_STICKY 不重启 · REDElIVER 重传 Intent。

### bindService 的 flags

第三个参数是 int，可以用 `|` 组合。学习页用的是 `Context.BIND_AUTO_CREATE`。

| flag | 意思 |
|---|---|
| **BIND_AUTO_CREATE** | 服务还没活，就先帮你 `onCreate` + `onBind`。最常用。 |
| **0（不传 AUTO_CREATE）** | 服务必须已经 start 过，否则这次 bind 连不上。 |
| BIND_DEBUG_UNBIND | debug 用，unbind 对不上时打调用栈。 |
| BIND_NOT_FOREGROUND | 这次绑定**不要**把对方进程抬到前台优先级。 |
| BIND_WAIVE_PRIORITY | 更彻底：不因这次绑定抬对方优先级。 |
| BIND_IMPORTANT | 相反：尽量把对方进程当前台重要进程。 |
| BIND_ABOVE_CLIENT | 服务比客户端还重要，客户端该杀时先别杀服务。 |
| BIND_ADJUST_WITH_ACTIVITY | 绑定来自 Activity，服务优先级跟这个 Activity 是否可见走。 |

`BIND_AUTO_CREATE` **不等于** `startService`：没人 bind、也没 start 时服务会销毁；既 start 又 bind 要两边都停才销毁。

### Broadcast

静态：清单声明；动态：register/unregister 成对。  
8.0+ 隐式静态基本失效。onReceive 超 10 秒 ANR。有序广播可 abort。LocalBroadcastManager 已废弃。

### ContentProvider

跨应用数据共享，Uri + ContentResolver。CRUD + getType。onCreate 在主线程，且可能早于 Application.onCreate。
