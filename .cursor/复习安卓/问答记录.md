## 第 1 轮

**题：Handler 是干什么的？四个角色怎么串起来？**

你的口述：

> handle 是用来做消息通讯。在 run 方法里创建 Looper.prepare，然后创建 handle，然后 sendMessage，然后 looper.next，就可以在 handle 的 handleMessage 回调里切换到主线程了。

点评：

- 对：知道 Handler 做消息通信；知道要 prepare、创建 Handler、sendMessage、再取消息。
- 错（关键）：这套 `prepare → new Handler → loop` 写在子线程 `run()` 里，`handleMessage` 跑的是**子线程自己**，不是主线程。切到主线程，Handler 必须绑主线程 Looper。
- 补：四个角色没点齐（少了 Message、MessageQueue）；取消息的是 `Looper.loop()` 里调 `queue.next()`，不是 `looper.next`；主线程 Looper 启动时已经准备好，不用自己 prepare。

结论：**方向对，线程切反了，这一题还没过。**

### 追问补答

**题：子线程想更新 UI，Handler 应该在哪创建？消息是谁发出、谁取出、谁执行？**

你的口述：

> 1. handler 应该在主线程创建。2. 消息应该是在主线程的 handler 发出、取出、执行。

点评：

- 对：Handler 在主线程创建（或 `new Handler(Looper.getMainLooper())`）。取出、执行也在主线程。
- 错：发出一般在**子线程**。子线程拿着主线程那个 Handler 调 `sendMessage` / `post`。如果发、取、执行都在主线程，就没有线程切换，只是同线程排队。

结论：**半对。记住：子线程发，主线程 Looper 取，主线程 Handler 执行。**

### 再答一遍

你的口述：

> 子线程里发是用 handler 调用 sendMessage/post，取消息是主线程的 loop 方法里 queue.next 取出，然后执行是在 handler 的 handleMessage 执行。

点评：对。发 / 取 / 执行分工说清了。第 1 题 Handler 四角色串流程，这轮算过。

## 第 2 轮

**题：主线程 Looper 是个死循环，为什么不会卡死、也不会 ANR？**

你的口述：

> 没消息时，主线程在休眠，不会 ANR。ANR 的原因是执行/消息响应超过 5 秒未响应。

点评：

- 对：没消息时休眠、不烧 CPU；ANR 是「有活却响应不了」，不是 loop 本身。
- 补：休眠卡在 `queue.next()` 里的 `nativePollOnce`，底层 `epoll_wait`，被内核堵住，不占时间片。有消息进来 `nativeWake` 才醒。
- 补：5 秒只是**输入分发**（触摸/按键）。广播 10s、前台 Service 20s、后台 Service 200s，不是所有 ANR 都是 5 秒。
- 一句话：loop 不是卡顿原因，往主线程塞耗时任务才是。

结论：**半对。方向过了，机制和时限还要补两句。**

### 再答一遍

你的口述：

> 1. 没消息时，主线程卡在 nativePollOnce 方法上。2. 5 秒对应是触摸或者点击事件。

点评：对。再带一句底层 epoll、有消息才 nativeWake，这题就完整了。第 2 题算过。

## 第 3 轮

**题：Handler 为什么会内存泄漏？怎么解决？**

你的口述：

> 修法就是让 handler 写成静态类，内部用弱引用持有 Activity，最后在 onDestroy 里 handler.removeCallback。

点评：

- 对：两种修法都点到了——静态内部类 + WeakReference；onDestroy 清消息。
- 漏：没说引用链。面试官先问「为什么」，再听修法。错的归因是「Handler 持有 Activity」；对的是 `MessageQueue → Message.target → Handler（非静态内部类）→ Activity`。根因是 **Message 比 Activity 活得长**（postDelayed 还在队列里）。
- 补：更完整的 API 是 `removeCallbacksAndMessages(null)`，一次清掉这个 Handler 的全部消息，不只 Runnable。

结论：**修法过了，泄漏链还要补。**

### 再答一遍

你的口述：

> MessageQueue → Message.target → Handler → Activity，因为 Message 比 Activity 活得长。

点评：对。引用链和根因都说准了。第 3 题过关。

## 第 4 轮

**题：子线程里能直接 new Handler 吗？**

你的口述：

> 默认不行。但是可以在子线程里用 Looper 开辟一个：Looper.prepare，然后创建 Handler，然后 Looper.loop。

点评：

- 对：默认不行；三步补齐说对了（prepare → new Handler → loop）。
- 补：为什么不行——子线程没有 Looper，`new Handler()` 里 `Looper.myLooper()` 从 ThreadLocal 取到 null，直接抛异常。
- 加分：现成方案是 HandlerThread，内部已经把这三步做完，`new Handler(ht.getLooper())` 即可。注意 `handleMessage` 跑在这个后台线程，不是主线程。

结论：**基本过。原因补一句更稳。** Handler 四连问到此收口。

### 插问：ThreadLocal 是什么？

口述要点：

- 线程局部变量：同一个 ThreadLocal，每个线程 set/get 拿到的是**自己那份**，互不看见。
- 实现：每个 Thread 里有一个 ThreadLocalMap，key 是 ThreadLocal（弱引用），value 是值。
- Looper 为什么用它：`Looper.prepare()` 往当前线程的 ThreadLocal 里 set 一个 Looper，所以天然一线程一个；再 prepare 会抛「Only one Looper」。
- Handler 构造：`Looper.myLooper()` = `sThreadLocal.get()`，子线程没 prepare 就是 null。
- 坑：key 弱、value 强。ThreadLocal 对象被回收后 value 还被长寿线程（线程池）握着会泄漏，用完 `remove()`。

**题：按 HOME、弹出普通 Dialog、旋转屏幕（没配 configChanges），各走什么生命周期？**

2. `create(XxxService)` 的实现类是手写的吗？你答「是的」。错。是动态代理，`Proxy.newProxyInstance` 生成，没有手写实现类。调用方法进 `InvocationHandler`，读注解拼 Request，再交给 OkHttp。
3. 再答：框架生成的。对。网络入门两问过关。

### 追问：addInterceptor vs addNetworkInterceptor

你的口述：不知道。

要点（先教再背）：

- `addInterceptor` = Application，最外层，一次请求只走一遍；缓存命中也走；适合加 Token、日志、加签。
- `addNetworkInterceptor` = Network，Connect 之后、真上网前，每次真实网络都走（重试/重定向会多次）；缓存命中不走；适合看真实报文。
- 一句话：Application 看最终账，Network 看线路上的每一次。

再答：

> addInterceptor 在最外层，一次请求只走一次。addNetworkInterceptor 每次真上网都走，缓存命中它不走。

点评：对。两种拦截器过关。

## 插问：Service 有哪些方法、生命周期

必会：onCreate（一次）→ start 走 onStartCommand（多次）/ bind 走 onBind（默认一次）→ onUnbind / onDestroy。混合启动要 stop + 全 unbind 才销毁。跑在主线程。

## 插问：BIND_AUTO_CREATE 和其他 bind flags

`bindService(intent, conn, flags)` 的第三个参数。学习页用 `BIND_AUTO_CREATE`：服务不在就先创建再绑。不等于 startService。还可以 `|` 组合优先级相关 flag（NOT_FOREGROUND / IMPORTANT / ABOVE_CLIENT 等）。

## 简历插问 1：MVC / MVP / MVVM 有什么区别？

口述要点：差在 View 和业务谁认识谁、数据怎么回界面。

- MVC：Activity 又当 View 又当 Controller，容易膨胀。
- MVP：Presenter 通过接口指挥 View，好测，但要 detach，否则泄漏。
- MVVM：ViewModel 不持有 View，页面观察 LiveData/Flow；旋转数据还在。

项目：多数页偏 MVC；别吹全项目 MVVM。
