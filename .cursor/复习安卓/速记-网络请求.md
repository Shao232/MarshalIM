# 网络请求口述：OkHttp → 发请求 → Retrofit

分工一句话：**OkHttp 真发网络；Retrofit 把「接口方法」翻译成 OkHttp 的 Request。**

项目对照：`WanAndroidHttpRequestFactory` 建 Client + Retrofit，`WanAndroidService` 写 API，`WanAndroidApi` 调用。

---

## 1. 先创建 OkHttpClient

```kotlin
okHttpClient = OkHttpClient.Builder()
    .addInterceptor(interceptor)          // 应用拦截器，日志/Token
    .writeTimeout(3000, TimeUnit.MILLISECONDS)
    .readTimeout(3000, TimeUnit.MILLISECONDS)
    .build()
```

Builder 里常配：超时、拦截器、Cookie、证书、连接池、缓存。  
`OkHttpClient` 应单例复用：它带着连接池和线程池，每次 `build()` 新的等于白建。

项目里每次 `getXxxRequest()` 都重新 build，面试可以说「生产上应做成单例」。

---

## 2. 不用 Retrofit，OkHttp 自己也能请求

```kotlin
val request = Request.Builder()
    .url("https://www.wanandroid.com/banner/json")
    .get()
    .build()

val call = okHttpClient.newCall(request)
// 同步（别在主线程）：call.execute()
// 异步：call.enqueue(callback)
```

一次异步请求怎么走：

```
newCall(request) → RealCall
  → enqueue → Dispatcher（最多 64 个，同 host 最多 5 个）
  → 线程池跑 → 拦截器链 → 写出请求、读回响应
  → 回调（还在线程池，要切主线程才能改 UI）
```

拦截器链（责任链，`chain.proceed`）：

1. 用户 Application Interceptor（`addInterceptor`，只走一次）
2. RetryAndFollowUp（重试、重定向）
3. Bridge（补 Header，gzip）
4. Cache
5. Connect（连接池 / TCP / TLS）
6. 用户 Network Interceptor（`addNetworkInterceptor`，每次真上网都走）
7. CallServer（真正写读）

`addInterceptor`：看最终账，缓存命中也走。  
`addNetworkInterceptor`：看真实上线路的每一次，缓存命中不走。

## 3. Retrofit：不发网，只翻译

```kotlin
retrofit = Retrofit.Builder()
    .client(okHttpClient)                 // ★ 把上面的 OkHttp 塞进去
    .baseUrl("https://www.wanandroid.com")
    .addConverterFactory(GsonConverterFactory.create())   // JSON ↔ 对象
    .addCallAdapterFactory(...)           // Call / Observable / suspend
    .build()

val service = retrofit.create(WanAndroidService::class.java)
```

`create` 是**动态代理**：没有手写实现类。调用 `service.getBanner()` 进 `InvocationHandler`：

1. 解析 `@GET("/banner/json")` → 拼 URL、组 Request
2. Converter 把 body / 响应和 Gson 互转
3. CallAdapter 决定返回 `Call` / `Observable` / suspend 的结果
4. 真正执行的还是 **OkHttp 的 Call**

接口长这样：

```kotlin
interface WanAndroidService {
    @GET("/banner/json")
    suspend fun getBanner(): Response<WanAndroidBaseBean<...>>
}
```

`suspend`：内部还是 `enqueue`，回调时 `resume`，看起来像同步。

---

## 4. 整条链路串起来

```
业务：WanAndroidApi.fetchBanners()
  → service.getBanner()          // 动态代理
  → Retrofit 拼 Request
  → OkHttpClient.newCall
  → Dispatcher + 拦截器链
  → 网络
  → Gson 转成 BannerBean
  → 回到协程 / 观察者
```

面试一句：

> 我先配好 OkHttpClient（超时、日志拦截器），再交给 Retrofit。  
> Retrofit 用动态代理把注解方法变成 Request，自己不发网。  
> 真正走连接池、重试、读写的是 OkHttp。

---

## 5. 必追

- Application vs Network 拦截器？（上面那表）
- Dispatcher 为啥限 64 / 每 host 5？限流在 Dispatcher，不在线程池。
- Retrofit 怎么实现的？动态代理 + 注解运行时解析 + ServiceMethod 缓存。
- CallAdapter vs Converter？前者怎么执行、返回啥；后者怎么序列化。
- ResponseBody 必须关，否则连接泄漏。
- 大文件下载加 `@Streaming`，不然整包进内存。

## 6. 设计模式（写了框架就会问）

原则：讲**干什么用这个模式**，类名说不准就别硬编。

### OkHttp

| 模式 | 在哪 | 口述 |
|---|---|---|
| **责任链** | 拦截器链 | 每个 Interceptor 拿 `Chain`，干完自己的事 `proceed()` 给下一个。加日志/Token 不用改发网代码。**这是第一必答。** |
| **建造者 Builder** | `OkHttpClient.Builder`、`Request.Builder` | 超时、拦截器、缓存可选，一步步拼再 `build()`。 |
| **工厂** | `Call.Factory`，`client.newCall(request)` | Client 按 Request 造出 `RealCall`。 |
| **享元 / 对象池** | 连接池 `ConnectionPool` | 同 host 复用 TCP，少握手。HTTP/2 一条连接多个流。 |
| **观察者** | `Callback`、`EventListener` | `enqueue` 成功/失败回调；DNS/TCP/TLS 各阶段也能听。 |
| **策略** | `Authenticator`、`Dns`、`CertificatePinner` | 换鉴权、换 DNS，不改调用方。 |

单例不是 OkHttp 内部强制的，是**你**应该只持有一个 Client，才能共用连接池。面试说「我们把 Client 做成单例」即可。

责任链源码就记流程：`getResponseWithInterceptorChain()` 把用户拦截器 + 内部 5 个装进 List，`RealInterceptorChain.proceed()` 下标 +1 递归。最后一个 `CallServerInterceptor` 不再 proceed，真正读写。

### Retrofit

| 模式 | 在哪 | 口述 |
|---|---|---|
| **动态代理** | `retrofit.create(Api)` | **第一必答。** `Proxy.newProxyInstance`，方法调用进 `invoke`，读注解拼 Request。 |
| **建造者** | `Retrofit.Builder` | baseUrl、client、Converter、CallAdapter 再 build。 |
| **外观 Facade** | Retrofit 整层 | 对外是「调接口方法」，对内藏着 OkHttp、注解、转换。 |
| **适配器 Adapter** | `CallAdapter` | 把 OkHttp 的 `Call` 适配成 `Observable` / `LiveData` / suspend。 |
| **工厂** | `Converter.Factory`、`CallAdapter.Factory` | 按返回类型挑 Gson 还是 Scalar、挑 Rx 还是协程。 |
| **享元 / 缓存** | `serviceMethodCache` | 同一个方法的注解只解析一次，放 ConcurrentHashMap。 |

和 OkHttp 的关系：Retrofit **外观 + 代理**，OkHttp **责任链发网**。不是两套发网。

### 1 分钟口述稿

> OkHttp 最核心是责任链：一串拦截器 `proceed` 往下传，日志、重试、缓存、连接各管一段。Client、Request 用的建造者。`newCall` 是工厂。连接池是享元。异步用 Callback 观察者。
>
> Retrofit 最核心是动态代理：`create` 不手写实现类，调用时解析注解。它是 OkHttp 的外观。CallAdapter 是适配器，Converter 是策略/工厂。解析过的方法会缓存。
>
> 真正上网的只有 OkHttp。

追问怎么接：

- 为啥用责任链？加拦截器不用改 CallServer。
- 动态代理和 APT 差？Retrofit 运行时反射，不生成 Java 源文件；ARouter 是编译期生成。
- 为啥 ServiceMethod 要缓存？反射贵，同一方法只解析一次。
